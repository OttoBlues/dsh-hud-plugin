# HUD V0.5.3 · 手动更新可靠性、纯色驾驶舱与入口简化

> 本版本是对 V0.5.2 实机反馈的修复候选，视觉与稳定性必须经过用户复验；尚未获 Released 正式批准。

## 修复根因与界限

截图证明 V0.5.2 在点击“检查更新”后停留在“扫描版本源…”，但不能仅凭截图断言是网络、配置编辑器还是热更新生命周期故障。源码检查发现两个**确定的缺陷模式**：

- Host 的 `checking` 在一个未结束的异步刷新任务期间持续为 true，五分钟后台扫描可能被跳过；原版仅单个请求 20 秒超时，并未对**整个索引扫描和配置写入**设置可靠界限。
- Client 使用 `checkState === 'checking'` 或残留 `checkNonce` 永久禁用按钮，没有超时恢复路径；如 Host 卸载或写设置失败，即使网络恢复仍会留在“扫描中”。

### V0.5.3 实施

1. Host 对整个发现过程施加 28 秒扫描信号和 6 秒 ConfigEditor 限时，确保即使上一次失败也能恢复后台轮询。
2. `checkNonce` 按真实请求身份处理，旧检查不能覆盖新一次重试的结果；尝试失败不以高频循环重复处理相同 nonce。
3. 前端新增 `checkQueuedAt`，区分队列与运行中；45 秒无回复即提示超时，重新允许点击，老版本遗留的无时间戳任务也能重试。
4. 组件中心显示最近后台扫描时间和状态；成功、部分通道失败、全源失败均有不同状态，不能误报“已是最新”。
5. 点击“检查更新”仍然只读取公开版本目录与通道，不执行安装，不改变三项自动更新授权，不依赖本地 Actions Runner。

## HUD 纯色视觉定案候选

| 类别 | 固定色 | 使用范围 |
| --- | --- | --- |
| 舱体底色 | `#071522` | HUD 全帧工作台 |
| 信息面板填充 | `#142b3a` | 任务、统计、会话等所有 HUD 面板 |
| 边框/结构线/高亮 | `#6dcbd2` | 所有 HUD 轮廓和切角线、分隔线与按钮边框 |
| 主文字 | `#e6f1f4` | HUD 主信息 |
| 次级文字 | `#a8bdc6` | HUD 辅助数据 |

设计限制：背景不得渐变；信息面板不得渐变；禁用发光文字、阴影、投影、虚假刻度或扫描动效。保留固定 12px 外切角和 11px 内切角，保证不变形。左侧导航和主按钮为纯色，面板填充统一，排版继续可适应窄窗。

## HUD 与 DSH 的职责边界

- DSH 左侧 HUD 插件入口与 HUD 组件中心继续存在，**仅组件中心保留“进入 HUD 模式”**。移除覆盖在原 DSH 主界面右上方的悬浮 HUD 按钮。
- HUD 模式仍有“返回 DSH”及“组件中心”，原 DSH 会话、权限审批、工作区不受影响。
- 组件中心继续采用 DSH 原生亮色/暗色主题与表单样式，不受深色 HUD 配色影响。
- Windows 最小化/最大化/关闭是 DSH/Electron 宿主窗口按钮。当前插件无经核实的官方主题控制接口，本版不尝试 DOM 或系统窗口级覆盖；若要求改色需后续 DSH 宿主层能力支持。

## V0.5.4 补充：V0.5.3 永久等待 Host 的确定性代码路径

用户的 Windows 截图和较早的 crash logs 无法提供本次超时的实际异常堆栈。但对 V0.5.3 发布代码审计确认：`processCheckRequest` 在写入 `checking` 成功之前就将 `lastCheckNonce` 设为当前请求，若 `writeSettings` 返回 false，同一请求会永久被后续计时器拒绝；`ConfigEditor` 及 Loader entry 又在 apply() 时只检索一次，如果当时服务未就绪则不会恢复。两者均可能导致用户报告的“排队等待 Host 检查 → 45 秒超时”。

V0.5.4 采取：每次写配置重新检索服务与 entry，缺失时写 Host 警告；仅在请求状态写入成功后记录 nonce；失败使用 3 秒退避后继续尝试相同请求，避免永久丢失；不把未能写回 DSH 的扫描误标为成功。增加模拟配置编辑器初始不可用、临时拒绝写入、恢复后同一个 nonce 成功的自动化回归测试。

此项并不证明用户设备唯一故障原因已经确定。下一步还应在 DSH Host 实机记录这些警告与请求阶段，验证修复。
