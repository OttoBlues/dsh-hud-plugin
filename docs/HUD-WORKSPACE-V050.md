# HUD V0.5.0 · 主界面替换与 DSH 双向切换

## 第一阶段目标

HUD 由旧的组件管理面板扩展为 DSH 窗口内的第二套全帧工作界面，视觉上覆盖原有 DSH 三栏布局。用户可随时返回原生 DSH 会话，而不重启程序或重建会话数据。

## 实现边界

- 通过官方 `shell.overlay` 插槽绘制全帧交互层，底层 DSH AppFrame 保持挂载。
- `hudMode` 默认 false；DSH 页面提供 HUD 小按钮，HUD 组件中心提供「进入 HUD 模式」，HUD 页面提供「返回 DSH」及「组件中心」。
- HUD 目前包含总览、真实会话名称、运行状态与数量，使用官方 `useSessions` / `useSessionStatus`；没有伪造的发送按钮。
- 对话输入、会话选择、文件操作、授权审批依然交由原生 DSH；退出 HUD 使用 `ctx.layout.selectPanel(null)` 保留当前 Session。
- 不是系统级透明 Windows 桌面 HUD，也不改变原生标题栏或窗口生命周期；透明/热键/点击穿透后续开发。

## U05 Desktop 人工验收清单

| 项目 | 操作 | 通过标准 |
| --- | --- | --- |
| U05-1 | 更新到 V0.5.0 后打开 DSH | 默认仍进入 DSH，会话与插件管理正常 |
| U05-2 | 点击 HUD 模式入口 | HUD 工作区覆盖整个 DSH 应用内容区域，返回 DSH 按钮可见 |
| U05-3 | 对照原生 DSH 会话状态 | HUD 显示真实名称和运行情况；无会话时为空态 |
| U05-4 | 在 HUD 点击返回 DSH | 返回原会话，输入草稿和 Session 不应丢失，无需手动重启 |
| U05-5 | 从 HUD 点击组件中心 | 关闭 HUD 并显示原有组件安装/更新管理面板 |
| U05-6 | 反复切换、缩小窗口、触发插件更新 | 无界面卡死、黑屏、消息丢失或审批流程受阻；始终有退出路径 |
