## 当前行动

- 验证新仓库地址 `OttoBlues/dsh-hud-plugin` 的无痕访问和 GitHub 连接授权。
- 已通过云端 CI 验证 V0.4.2 固定安装包并加入 Unstable；用户确认本机升级成功、无报错、无需手动重启。
- 继续核对 HUD 的中英文仓库说明、新 Raw 源和故障处理；后续可评估更新后保留 HUD 页面而非返回主会话。
- 不再启用本机 Actions Runner，CI 不再具备部署或卸载 Desktop 的路径。
- 区分当前插件组件热重载与整个 DSH 进程重启（尚未验证）；Released 通道仍为空，未经用户明确批准不得升为正式版。

## V0.5.0 工作区阶段

- 先实现安全可逆的 HUD 视觉工作区，保留原 DSH 主会话和所有权限。
- 在 HUD 中提供总览、真实会话状态和返回 DSH/组件中心的可见出口。
- 对新版本的 U05 验收重点：默认 DSH、进出 HUD 不丢失 Session、更新或插件停用不锁住原 UI。
- Windows 系统级透明置顶/点击穿透仍属于之后的 M4，而不是本次全帧 HUD 工作区。

## V0.5.1 用户视觉验收目标

- HUD 工作区从大块圆角 Dashboard 改成矢量切角、可辨读的细线框驾驶舱面板。
- 组件中心同步采用同套切角面板、控件描边及轻微网格。
- 用户点击「检查更新」应在当前 DSH 会话里更新索引，不必重启应用；不自动安装。
- 错误场景必须解释失败的是仓库总索引还是某个发布通道，不得显示假的“已是最新”。
- 仍需用户实机确认颜色强度、信息密度、视觉节奏和 HUD/DSH 切换可靠后才敲定视觉规范。

## V0.5.2 新视觉任务书

以 [V0.5.2 视觉修正任务书](HUD-VISUAL-REFORM-V052.md) 为准；核心是修复拉伸 SVG 变形、减少 HUD 线条和网格噪声、强化模块实体层次，同时将组件中心交还给 DSH 原生浅/深色主题。保留手动检查更新、不自动安装、原会话返回及 Unstable/Released 隔离。

## V0.5.3 修复范围

优先解决用户 V0.5.2 观察到的手动检查无响应，以及后台五分钟检查缺少可见证据的问题。增加超时失败恢复与后台最近检查状态；HUD 取消全部渐变和阴影统一线、面板纯色；原 DSH 页面移除悬浮 HUD 入口，仅从组件中心切换。原生 Electron 标题栏按钮需 DSH 宿主支持而非 HUD 插件 DOM 覆盖。按 [U053 验收](HUD-UPDATE-FLAT-V053.md) 审查。

## V0.5.7 独立窗口任务

详见 [Windows 独立 HUD 设计及 U057 验收](HUD-NATIVE-WINDOW-V057.md)。使用 Host 管理本机 WPF 辅助进程；主窗口只在 HUD 成功显示后隐藏，返回/异常退出时恢复；版本查询与安装机制保持原有隔离。

## U058 修复重点

v0.5.7 无窗口、仅显示超时。修复使用官方 Connection RPC，返回真正的 WPF 启动结果与具体失败原因；详见 [v0.5.8 排障与验收](HUD-NATIVE-WINDOW-V058.md)。

## V0.5.9 更新生命周期修复

DSH 一次进程仅允许升级一次并非官方限制。由用户报告的多次更新卡住、重启后生效和 HUD 启动 HTTP 405，追踪到原 Host 临时配置写入可能触发重组和已安装/已运行版本不一致；参见 [修复设计和 U059 验收](HUD-INSTALL-RELIABILITY-V059.md)。更新包只进入 Unstable，Released 保持空。

## V0.5.10 修复计划

v0.5.9 的用户截图进一步证明公开源初始化假不可用、HUD Host 路由 HTTP 405、复选框无反馈不可保存。v0.5.10 缩减 Host 必需服务并显式显示设置写入状态，自动初始化公共 GitHub 只读扫描，见 [U0510 验收](HUD-SETTINGS-BOOTSTRAP-V0510.md)。

## V0.5.11 更新策略与独立窗口修复尝试（未发布）

针对本机观察到的 `status=unavailable, writable=true` 仍无法保存，以及 WPF 辅助窗体按 `process.ppid` 搜索而命中 Explorer 的故障，改为仅依据 DSH `writable` 描述决定提交许可，并以当前 DSH 进程 PID 定位拥有 BrowserWindow 的窗口。恢复时只匹配 `Chrome_WidgetWin_1` 主窗，忽略同进程隐藏辅助窗；无唯一目标或窗口仍隐藏时不再报告成功。另为中文 WPF 脚本添加 UTF-8 BOM，避免 Windows PowerShell 5.1 按本地代码页解析。自动化回归、Windows WPF 自检和 U0511 DSH 实机操作分别记录，不以构建结果替代实测。

## V0.5.12 独立窗口冷启动超时修复

本机 WPF 冷启动约 17 秒才输出 READY，超过 V0.5.11 的 16 秒 Host 超时，并可能在强制关闭计时器前误接收迟到 READY。Host 等待提高至 45 秒，Client RPC 等待提高至 55 秒；超时后收到的 READY 会被拒绝、结束辅助进程并尝试恢复 DSH 主窗。策略保存、真实独立窗口打开与返回仍需用户在当前 DSH 验收。
